# PR-5 plan: the skill collapse (design §4, §7.2, §10 item 5)

**Status:** proposal for maintainer decision, 2026-09-22. Measured on main `28ad626` (= ci-prod), after #197/#198. Five inventories (`/tmp/rfe-pr5-inventory/*.json`, 635 items: skill trees with per-pair diff classification, every skill-name reference outside the skills, stale and dead paths, the remaining type-literal code, eval and production coupling) back every number below.

**What the collapse is.** Twenty-one directories, 33 files, 3,448 lines under `.claude/skills/`. Six `rfe.<verb>` bodies and six `initiative-<verb>` twins whose diffs are, per pair, overwhelmingly token swaps (review SKILL: 37 of 50 change blocks; auto-fix: 11 of 12; speedrun: 32 of 48; submit: 8 of 11; split SKILL: 28 of 39) with a known set of structural divergences (rfe-only: rubric export step, `size=`, `rebuild-index`, comments companion, Phase-1 create barrier, the dead `autofix` return; initiative-only: `--parent`/alignment dimension, explicit error-stub command, Phase-4 `batch_summary`). Judgement prose that must stay typed is concentrated where §4.2 said it would be: `split-agent.md` (22 of 43 blocks typed), `revise-agent.md` (8 of 16), `review-agent.md` (4 of 16), the create templates and guidance. Three live dimension skills (`rfe-feasibility-review`, `initiative-feasibility-review`, `strategic-alignment-review`) are launched by prose and by `pipeline_state.py` as `prompt_file:` waves — never through the Skill tool. Four orphan strat reviewer skills (`architecture-review`, `feasibility-review`, `scope-review`, `testability-review`) are referenced by nothing in this repo.

**What already exists for it.** The descriptors carry every value the generic bodies need — `pipeline.prompts.{create_guidance, review_rules, review_sections, revise_rules, split_rules}`, `pipeline.dimensions[]`, `pipeline.scorer_agent`, `pipeline.rubric.*`, `dirs.*`, `identity.*`, `pipeline.poll_prefix` — all pointing at *today's* legacy paths with inline comments saying the `types/<t>/prompts/*` move is PR-5; the schema already types them as repo paths "consumed via launcher vars from PR-5"; gate 1 already checks they exist. `pipeline_state.py` already imports the registry and reads `dirs` from it in two places; its one remaining literal table is `PIPELINE_TYPES` (lines 175–200: `review_prompts`, `split_prompt`, `scorer_type`, `rubric_path`, `feasibility_skill`, `alignment_skill`, `tasks_dir`, `reviews_dir`, `dispatch_skill`, `poll_prefix`). `fetch_issue.py --fetch-all --type <t>` exists (PR-3c), so the Tier-1 fetch skeleton has its one writer. The eval configs are generated (PR-4), so the `skill:` flip is a fragment/generator change, not a hand edit. The rubric checkout is pinned (#198), so the evals that gate this series measure a fixed scorer.

**Prerequisites and non-goals.** ci-prod at `28ad626` or later. The §7.2 scorer collapse (one `rfe-scorer` name across types, a coordinated assess-rfe change) stays out: `pipeline.scorer_agent` remains per type and the generic bodies read it from the registry. The neutral-branding question (`request-*`, D1 of §11) stays deferred. The optional autofixer prompt flip to `/rfe-auto-fix` is PR-10. Rubric v2 is PR-6.
